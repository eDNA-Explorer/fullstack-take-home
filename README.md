# eDNA Explorer Take-Home Challenge

This project consists of a data pipeline (Dagster) and a dashboard (Next.js). The pipeline generates mock genomic data and outputs Parquet files that the dashboard consumes via tRPC.

## Project Structure

```
edna-take-home/
├── data-pipeline/       # Dagster data pipeline
│   ├── samples/         # 16 FASTQ files (8 samples, paired-end)
│   ├── output/          # Generated Parquet files
│   └── src/data_pipeline/defs/
│       ├── sample_list.py
│       ├── sequence_counts.py
│       └── sample_stats.py
└── dashboard/           # Next.js dashboard
    ├── app/page.tsx     # Main dashboard page
    └── server/routers/samples.ts
```

## Getting Started

### Prerequisites

This project uses [mise](https://mise.jdx.dev/) to manage tool versions (this is optional and just for your convenience). Install mise and run:

```bash
mise install
```

This will install the correct versions of:
- **Bun** - JavaScript runtime for the dashboard
- **Node.js 22** - Required for some tooling

### Data Pipeline

```bash
cd data-pipeline
docker-compose up
```

Dagster UI will be available at http://localhost:3000

### Dashboard

```bash
cd dashboard
bun install
bun dev
```

Dashboard will be available at http://localhost:3001

## Challenge 1: Sample List & Sequence Counts

### 1.1 Update Sample List Asset

Update the mock asset in `data-pipeline/src/data_pipeline/defs/sample_list.py` to utilize the actual sample data in `data-pipeline/samples/`.

- The directory contains 16 FASTQ files for a total of 8 samples
- Each sample has a forward and reverse pair (R1/R2)

### 1.2 Update Sequence Counts Asset

Update the mock asset in `data-pipeline/src/data_pipeline/defs/sequence_counts.py` to build a Parquet dataframe providing `total_reads` per sequence per sample.

### 1.3 Update Dashboard Endpoint

Update the tRPC endpoint in `dashboard/server/routers/samples.ts` to load the total reads from `output/sequence_counts.parquet`.

### 1.4 BONUS: Compression Optimization

We are deliberately using an ineffective compression algorithm on our Parquet output. Can you identify another TypeScript library which can support zstandard compression?

If so, update the endpoint to utilize this library and adjust the Polars output to use its default behavior for optimal performance.

## Challenge 2: Sample Stats with Seqkit

### 2.1 Update Sample Stats Asset

Update `data-pipeline/src/data_pipeline/defs/sample_stats.py` to run `seqkit` on each sample to derive the stats for Q30, Q20, etc. and write them to the Parquet output. See the documentation on seqkit's `stat` command here:
https://bioinf.shenwei.me/seqkit/usage/#stats

### 2.2 Parallelize with Graph-Backed Assets

This work can be parallelized in Dagster. Rewrite this asset to utilize a graph:
https://docs.dagster.io/guides/build/assets/graph-backed-assets

This enables seqkit to be run in parallel across many samples.

> **Note:** If you get stuck here, just process them in sequence via a simple loop.

### 2.3 Update tRPC Endpoint

Update the tRPC endpoint from Challenge 1 to load the true stats from your data pipeline.

### Prerequisites

Complete Challenges 1 and 2 before starting this challenge.

Reference: https://www.shadcn.io/charts/bar-chart/bar-chart-04

- A dropdown to select a sample

## Technical Notes

- The dashboard uses `parquetjs-lite` which has limited encoding support
- Parquet files must be written with `use_dictionary=False` and `version="1.0"` for compatibility
- The data pipeline outputs are synced via Docker volume to `data-pipeline/output/`
